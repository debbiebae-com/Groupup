# AEGIS SIEM — Log Monitoring Dashboard

A real-time Security Information & Event Management (SIEM) console: ingest telemetry from
multiple sensor types, evaluate streaming detection rules, triage alerts, and inspect raw
normalized events.

> All telemetry is generated by a local simulation engine. No external services or networks are
> contacted, and no credentials are required.

## Highlights

- **Live telemetry stream** over Server-Sent Events (SSE) with pause/resume and toast notifications.
- **Overview dashboard** — ingest volume by severity, severity mix, active incidents, top offender IPs,
  origin countries, rule hits, SOC activity, and live KPIs (events, alerts, MTTD, source health).
- **Log explorer** — full-text search, severity multi-select, source and time-window filters,
  live tail, paginated history, CSV export, and a raw ECS-style event drawer with JSON viewer.
- **Alert triage** — queue tabs, severity filters, assignment, status transitions
  (open → investigating → resolved), entity pivots, ATT&CK mapping, and correlated timelines.
- **Detection rules** — 13 analytic rules with thresholds, log sources, MITRE coverage, per-rule
  enable/disable, and 24-hour match counts.
- **Data sources** — per-collector health (healthy / degraded / offline), EPS, 24h volume, error rate,
  sparkline history, ingest distribution, and pipeline diagnostics.
- **Attack simulation** — inject six realistic scenarios (brute force, port scan, ransomware,
  exfiltration, C2 beaconing, cloud IAM abuse) and watch detections fire within seconds.

## Run locally

```bash
npm install
npm run dev
```

Open <http://localhost:4000>. The Express server hosts the API and mounts Vite in middleware mode,
so the app, API, and event stream share a single port.

### Production

```bash
npm run build
NODE_ENV=production npm start
```

The server serves the built SPA from `dist/` and exposes the same `/api` routes.

### Type checking

```bash
npm run typecheck
```

## Architecture

```
server/
  index.ts            Express app: REST API, SSE hub, simulation loop, Vite/static hosting
  engine/
    catalog.ts        Sources, countries, rules, seeded alerts, hosts, users
    events.ts         Realistic noise generators + attack scenario builders
    store.ts          Event buffer, aggregate stats, detection engine, alert lifecycle
shared/
  types.ts            Types shared by client and server
src/
  pages/              Overview, Logs, Alerts, Rules, Sources
  components/         Layout, charts, dashboard panels, log drawer, UI primitives
  lib/                API client, live SSE store + toasts, formatting helpers
```

### Detection engine

Every generated event batch is normalized and evaluated against the enabled rules in
`server/engine/store.ts`. Detectors group events within short windows (e.g. ≥ 6 failed sign-ins
from one IP, ≥ 15 denied connections, ≥ 3 periodic C2 beacons) and apply a per-rule/entity
cooldown to suppress duplicate alerts. New alerts are broadcast instantly over SSE, appended to
the triage queue, and reflected in KPIs.

Two background jobs drive the demo:

- **Noise** — 5–11 events every 1.1 s across firewalls, EDR, identity, cloud, DNS, and proxy.
- **Scenarios** — an attack is injected automatically roughly every 2.5 minutes, and manually via
  the **Simulate attack** menu.

## API

| Method | Path                     | Purpose                                         |
|--------|--------------------------|-------------------------------------------------|
| GET    | `/api/summary`           | KPI summary used by the shell                   |
| GET    | `/api/overview?range=`   | Aggregates for `1h`, `6h`, `24h`, `7d`          |
| GET    | `/api/logs`              | Query buffered logs (`q`, `severity`, `source`, `minutes`, `cursor`) |
| GET    | `/api/logs/export`       | CSV export of the current query                 |
| GET    | `/api/alerts`            | Alert queue (`status`, `severity`, `q`)         |
| PATCH  | `/api/alerts/:id`        | Update status / assignee                        |
| GET    | `/api/rules`             | Detection rule library                          |
| PATCH  | `/api/rules/:id`         | Enable or disable a rule                        |
| GET    | `/api/sources`           | Collector health                                |
| POST   | `/api/simulate`          | Inject an attack scenario                       |
| GET    | `/api/stream`            | SSE stream (`summary`, `sources`, `logs`, `alert`, `alert_update`) |

## Notes

- The log search buffer holds the most recent 60 minutes (up to 6,000 events server-side,
  500 client-side) — long-range charts use pre-aggregated statistics.
- Alert IDs continue from `ALT-1043` so the seeded queue and live detections share one sequence.
- Fonts: Inter and JetBrains Mono (self-hosted via Fontsource).
